# 出力テンプレート（Zenn 記事ドラフト）

以下の構成で本文を生成する。各セクションの長さは目安。全体で 1,800〜3,500 文字程度を狙う（発表数によって増減）。

---

## 1. タイトル

H1 は付けない（Zenn はフロントマターの `title` を見出しにするため）。

## 2. はじめに（150〜300字）

`## はじめに` という見出しを付けて、記事の冒頭に置く。

### 初回限定の必須要素

- **冒頭の自己紹介**: 「こんにちは、URBAN HACKSでバックエンドエンジニアをしている ◯◯（あだ名） です。」の形で書く（ユーザーにあだ名を確認する）
- URBAN HACKS のバックエンドエンジニアコミュニティで週1回「技術共有会」を開催していること
- 共有会の目的: 各チームの知見をコミュニティ全体で活かすこと。「あの話、誰かがしてたな」とふと思い出せるインプットの積み重ねをイメージ
- 発表スタイルはカジュアル（資料なし・箇条書きOK）。テーマも技術に限らず何でもOK
- チームごとの持ち回りで、普段別プロジェクトで働くメンバー同士のコミュニケーションや、ノウハウ交換・議論が起きることも狙い
- 1か月分の発表をまとめた月次サマリーとして届けることを明示する
- **今回がシリーズ初回であること**を明示する
- 「定期的にお届けしていきます」を一言入れる（「毎月」など頻度を断言しない）

### 2回目以降

- 冒頭自己紹介は省略してよい（継続読者には不要）
- シリーズ趣旨（週1回の共有会の月次サマリー）を1行で再掲（前回記事へのリンクが入れられればなお良い → ユーザー確認）
- 今回が第N回であることを書く

## 3. 今月の共有テーマ（100〜200字）

今回の発表に通底するテーマを1〜2行で言語化したうえで、各発表のタイトルだけを箇条書きで先出しする（読者の地図になる）。

例:

> 今回のテーマは「観測性をどう高めるか」。チームの中で並行して進んでいる取り組みから、3本の発表がありました。
>
> - 〇〇〇〇
> - 〇〇〇〇
> - 〇〇〇〇

## 4. 各発表の紹介（1発表あたり 400〜700字 × 発表数）

発表ごとに以下の構成で書く。H2 を発表タイトル、H3 で内訳を作る。

**各発表セクションの冒頭に必ず1〜2行の要約（サマリー行）を入れること。**
その発表の「一言で言うと何の話か」を読者がつかめる文にする。
発表概要をそのまま転記せず、記事の読者に向けて再解釈した形で書く。

```markdown
## 発表タイトル（公開OKな表現に整える）

発表者: ◯◯ さん

（サマリー段落: この発表を一言で表す1〜2文。例: 「OpenTelemetry を試験導入し、既存ログとの棲み分け方を探った話です。自動計装の便利さと、サンプリング設計の難しさが浮き彫りになりました。」）

### どんな内容だったか
3〜5行。背景 → 取り組み → 結論 / 学び の流れで再構成する。発表者表記は「実名公開OK」の場合のみ実名、それ以外は「バックエンドエンジニアの一人」などに一般化する。

### 技術的に面白いポイント
発表のコアになる技術的トピックを1〜3点。一般化して書き、社内固有名詞は出さない。コード例や図は「社外公開してよい内容」に明示された範囲のみ使う。

### 読者に伝わる学び
読者（同じ領域のバックエンドエンジニア）が持ち帰れる示唆を1〜2点。「自分のプロジェクトでも試せそう」と思える形で書く。
```

## 5. 全体を通した所感（150〜300字）

- テーマに対して、このバックエンドチームがどう向き合っているかを短く言語化
- 「議論が起きた」「異なる視点が出た」など、共有会の場としての価値を匂わせる
- 「正解を出す場」ではなく「学び合う場」であることが伝わるとよい

## 6. 次回以降へのつなぎ（50〜100字）

- 「引き続き定期的にお届けしていく予定です」程度に留める（頻度・テーマを断言しない）
- 「興味のある方はぜひ URBAN HACKS の Zenn をフォローしてください」で結ぶ
- 次回予告や「月1回」などの具体表現は入れない

## 7. （任意）We are hiring 的な一言

URBAN HACKS 採用ページや会社情報へのリンクが付けられる場合のみ、短く添える（押し売りにならない程度）。リンクが用意されていなければ省略する。

## ドラフト出力サンプル（雛形）

実際にユーザーに返す Markdown は、以下のような形になる（中身は埋める）。

```markdown
## はじめに

こんにちは、URBAN HACKSでバックエンドエンジニアをしている ◯◯ です。

URBAN HACKSのバックエンドエンジニアコミュニティでは、週1回のペースで「技術共有会」と呼んでいる集まりを開いています。各チームが持っている技術的な知見やノウハウをコミュニティ全体で活かすことが目的で、「あの話、誰かがしてたな」とふと思い出せるくらいのインプットを積み重ねていくイメージです。

発表のスタイルはカジュアルで、資料なし・箇条書きレベルでもOK。名前に「技術」とついていますが、テーマは技術に限らず、自己紹介や健康ネタなど話し手が持ち寄ったものなら何でもOKです。チームごとの持ち回りで発表者を決めており、普段は別プロジェクトで働いているメンバー同士のコミュニケーションが生まれること、また発表をきっかけに「前の組織ではこうしてました」といったノウハウの交換や議論が起きることも狙いのひとつです。

この記事はその1か月分の発表をまとめた月次サマリーです。今回が第1回となります。

定期的にお届けしていく予定です。バックエンドまわりに興味のある方はぜひ。
```

## Zenn フロントマター案の雛形

```yaml
---
title: "（選んだタイトル案）"
emoji: "📡"            # テーマに合わせて1文字
type: "tech"
topics: [backend, techblog, ...]   # 技術キーワードから3〜5個。小文字・ハイフンなし推奨
published: false        # 必ず false。確認後に手動で true に
---
```
