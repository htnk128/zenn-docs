# タイトル案を複数出すルール

タイトルは記事の流入を決める最重要要素。1案だけ提案して終わらせず、必ず **3〜5案** を出し、おすすめを1つ明示する。

## 出す案数

- **必須**: 3〜5案
- 1案ずつは方向性を変える（後述の「方向性」を3つ以上カバー）

## タイトルの方向性（少なくとも3方向を出す）

毎回、以下のうち3方向以上を含む案を作る。

### 1. シリーズ色を出す方向

- 例: 「URBAN HACKS バックエンド技術共有会 第1回レポート」
- 例: 「【バックエンド技術共有会 vol.1】観測性を高める3つの取り組み」
- 利点: シリーズ感が明確で、リピート読者が見つけやすい
- 欠点: 単体記事としての「読みたさ」は弱め

### 2. テーマを前面に出す方向

- 例: 「観測性を高める3つの取り組み — URBAN HACKS バックエンド共有会レポート」
- 例: 「LLMを業務に活かすには？ — バックエンドチームで議論したこと」
- 利点: テーマで検索流入が見込める
- 欠点: シリーズ感はやや薄れる

### 3. 数字・具体性を入れる方向

- 例: 「3本の発表で見えてきた『観測性』へのチーム視点」
- 例: 「バックエンドエンジニアが今気になっている技術トピック3選」
- 利点: クリックされやすい
- 欠点: 煽りに寄りすぎないよう注意

### 4. 問いかけ・カジュアル方向

- 例: 「最近バックエンドチームで何を話してた？ — 技術共有会レポート vol.1」
- 利点: 採用広報的にチームの雰囲気が伝わる
- 欠点: 検索性は弱め

## NGパターン

- 「最強」「神」「爆速」など過剰な煽り
- 「○○な人は必見」「絶対知っておくべき」など断定的・煽り系
- 釣りタイトル（本文と乖離した刺激的見出し）
- 他社・他技術を貶める比較
- 社内固有名詞をそのまま含むタイトル（例: 「弊社の予約管理システム Foo の話」）

## 文字数と Zenn 流の慣習

- **30〜45 文字** を目安（短すぎず、長すぎず）
- 副題は「 — 」または「：」で区切る
- 絵文字はタイトルには入れない（Zenn は別途 `emoji` フィールドで設定）
- 「【】」付きのシリーズタグは1〜2語で短く

## 出力フォーマット

ユーザーに返すときは、以下の形でリスト化する。

```markdown
## タイトル案

1. **【おすすめ】観測性を高める3つの取り組み — URBAN HACKS バックエンド技術共有会 vol.1**
   - テーマ前面 + シリーズ色のバランス型。検索性とリピート読者の両方を取りに行ける。
2. URBAN HACKS バックエンド技術共有会レポート vol.1 — 「観測性」を語った夜
   - シリーズ色強め。雰囲気重視の読者向け。
3. バックエンドチームで「観測性」を3方向から議論してみた
   - テーマ前面・カジュアル寄り。Zennトップで目に留まりやすい。
4. 第1回 URBAN HACKS バックエンド技術共有会：観測性をどう高めるか
   - フォーマル寄り。社外向け技術広報トーン重視ならこちら。
```

おすすめを **必ず1つ明示** し、なぜそれを推すかを1行で添える。
