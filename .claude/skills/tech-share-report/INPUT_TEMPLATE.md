# インプットHTMLの書き方ガイド

発表内容は `articles/tech-share-reports/YYYYMM/<発表タイトル>/index.html` に HTML ファイルとして配置する。Notion からの HTML エクスポートがそのまま使える。

## ファイルの配置

```
articles/tech-share-reports/
└── YYYYMM/                          # 例: 202606
    └── 発表タイトル/                 # 日本語・英語どちらでもOK
        └── index.html
```

発表が複数ある場合は、発表ごとにディレクトリを分けて配置する。1つの発表の資料が複数ファイルに分かれる場合は、同じディレクトリ内に `index.html`, `index2.html`, ... と連番で置く。

```
articles/tech-share-reports/202606/
├── OpenTelemetryを試した話/
│   └── index.html
├── Cloudflare周りの共有/        # 資料が2ファイルの場合
│   ├── index.html
│   └── index2.html
└── Remotionでプロフィールムービーを作った話/
    └── index.html
```

## HTMLに含めるべき情報

Skill がテキスト抽出で読み込むため、以下の情報が HTML 内に含まれていれば記事化できる。

### 必須

- **発表タイトル**: `<title>` タグまたはページ冒頭の `<h1>`
- **発表の目的・概要**: 何を話したか、なぜその話をしたか
- **技術キーワード**: 使用したOSS・言語・サービス名

### あると品質が上がる

- **きっかけ・背景**: なぜこの取り組みを始めたか
- **技術的なポイント・学び**: コード例、設計の判断、気づき
- **よかった点・課題**: 試してみた結果の所感
- **まとめ**: 発表の結論・次のアクション
- **参考リンク**: 公式ドキュメント・公開ブログなどの外部URL

### Skill が社外公開可否を判断するために必要

以下のいずれかを HTML 内に明記しておくと判断がスムーズになる。

- **発表者の表記**: 実名を記事に出してよいか（記載があれば Skill が確認事項に挙げる。記載なければ匿名扱い）
- **社外公開NGの内容**: 社内システム名・顧客名・数値など、記事に出せない内容をメモしておく

明記されていない場合、Skill は [DISCLOSURE_GUIDE.md](./DISCLOSURE_GUIDE.md) の自動NG項目に従って判断し、グレーゾーンはユーザーへの確認事項として挙げる。

## Notion エクスポートをそのまま使う場合

Notion ページを「HTML としてエクスポート」して配置すれば、そのまま Skill が読み込める。以下の点だけ注意する。

- エクスポートで生成される CSS は長いが、Skill がテキスト抽出するので問題ない
- 画像ファイルは Skill が読まないため、画像の内容は本文テキストで補足しておくと記事に反映されやすい
- 内部リンク（Notion ページ間リンク）は参照できないので、重要な情報は本文に直接書く

## HTMLが準備できていない場合

HTML がまだない場合は、Skill が入力フォームとして [INPUT_TEMPLATE.md](./INPUT_TEMPLATE.md)（このファイル）を案内する。

その場合は以下のような最小情報を会話に直接貼り付けることでも記事化できる。

```
発表タイトル: 
開催日: YYYY-MM-DD
発表者表記: （実名 or 「バックエンドエンジニア」など）
発表概要: 
技術キーワード: 
公開してよい内容: 
公開NGの内容: 
補足: 
```
