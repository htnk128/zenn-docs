# 技術共有会レポート記事ドラフト作成 Skill

URBAN HACKS バックエンドエンジニアコミュニティで週1回開催している「技術共有会」のレポート記事を、Zenn の URBAN HACKS Publication (https://zenn.dev/p/10q89s) 向けに作成するための Skill。

この記事は**月次サマリー**として毎月1本発行することを想定している。その月の複数回分の共有会で出た発表内容を社外向けにまとめて届けることが目的。

## このSkillが目指す品質

- **シリーズで読まれる**: 構成・トーンを毎回統一し、読者が次回も読みたくなる
- **採用広報につながる**: チームの学習文化・技術への向き合い方が自然に伝わる
- **安全に公開できる**: 社外秘・個人情報・未公開システム名を出さない
- **読み物として面白い**: 単なる発表羅列ではなく、テーマで束ねた再構成にする

## インプットの形式

発表内容は `articles/tech-share-reports/YYYYMM/<発表タイトル>/` ディレクトリに HTML ファイルとして配置される。これは記事化前に一時的に置かれるもので、Notion などからエクスポートした HTML が想定される。

1発表が1ファイル（`index.html`）の場合と、複数ファイル（`index.html`, `index2.html`, ...）に分かれる場合がある。ディレクトリ内の HTML ファイルをすべて読み込み、同じ発表の資料として統合する。

Skill は Read ツールでこれらの HTML を読み込み、テキストを抽出して記事化素材として使う。HTML が未配置の場合は [INPUT_TEMPLATE.md](./INPUT_TEMPLATE.md) を案内する。

**配置パス例**:
```
articles/tech-share-reports/202606/
├── AIエージェントとRemotionでプロフィールムービーを作ろうとしている話。/
│   └── index.html
├── Cloudflare周りの共有/
│   ├── index.html      # 資料が2ファイルに分かれている場合
│   └── index2.html
└── 別の発表タイトル/
    └── index.html
```

## 利用フロー

ユーザーから「技術共有会の記事を作りたい」と依頼されたら、以下の順で進める。

### 1. HTMLファイルを読み込む

`articles/tech-share-reports/YYYYMM/` 配下を探索し、発表ディレクトリごとに含まれる HTML ファイルをすべて（`index.html`, `index2.html` など）Read ツールで読み込む。YYYYMM が指定されていなければユーザーに確認する。複数ファイルがある場合は内容を統合して1発表分の素材として扱う。

複数ファイルのうち、社内URL・社内固有名詞・内部認証情報など社外公開NGの内容が主体と判断したファイルは記事化に使用せず、「確認が必要」事項リストにその旨を明示してスキップする。

HTML から以下の情報を抽出する。

- 発表タイトル（`<title>` または `<h1 class="page-title">`）
- 発表者（自己紹介セクション）
- 発表の目的・背景・内容
- 技術キーワード（使用技術・OSS名など）
- 参考リンク（`<a href>` の外部URL）

### 2. 初回か継続回かを確認する

HTML を読み込んだ後、ユーザーに「シリーズ初回か、2回目以降か」を確認する。

- **初回**: `## はじめに` セクションを冒頭に置き、シリーズ趣旨を説明する導入文を入れる。冒頭に自己紹介（「こんにちは、URBAN HACKSでバックエンドエンジニアをしている ◯◯ です。」）を必ず入れるため、**記事執筆者のあだ名をユーザーに確認する**。
- **2回目以降**: 自己紹介は省略し、初回への言及・シリーズの継続感を出す

### 3. 社外公開可否を判断する

HTML に記載されている内容を [DISCLOSURE_GUIDE.md](./DISCLOSURE_GUIDE.md) に照らして判定する。

- 社外NGと判断した要素はドラフトに含めず、「確認が必要」事項リストに入れる
- 発表者の実名は、HTML に実名が書かれていても **ユーザーへの確認なしに記事へ出さない**（確認事項に挙げる）
- URBAN HACKS はあだ名文化のため、ユーザーがあだ名を提供した場合は「発表者: ◯◯ さん」の形で各発表セクションの冒頭（サマリー行の直前）に記載する

### 4. 今回の「テーマ」を1〜2行で言語化する

複数発表に共通する切り口・問題意識を1〜2行で言語化する。例: 「観測性をどう高めるか」「LLM を業務にどう組み込むか」「設計の選択肢と判断軸」など。テーマがどうしても見つからない場合は「バックエンド回り全般の知見共有」のような汎用テーマで構わないが、可能な限り絞る。

### 5. タイトル案を複数出す

[TITLE_RULES.md](./TITLE_RULES.md) のルールに従い、必ず **3〜5案** を提示し、ユーザーに選択してもらう（または合議で決める）。1案だけ出して終わらせない。

### 6. ドラフトを生成する

[OUTPUT_TEMPLATE.md](./OUTPUT_TEMPLATE.md) の構成に従ってドラフトを書く。書き終えたら本文中で [CHECKLIST.md](./CHECKLIST.md) を順に確認し、問題がなければユーザーに「公開前チェック結果」も併記して返す。

### 7. 記事ファイルを作成して本文を書き込む

ユーザーがタイトルを確定・承認したら、以下の手順で記事ファイルを作成する。

1. `npx zenn new:article` を実行して14桁スラッグのファイルを `articles/` に生成する
2. 生成された `articles/<slug>.md` を Read してからフロントマター（`title`, `emoji`, `type: tech`, `topics`, `published: false`）と記事本文を Write で書き込む

`published` は **必ず `false`** で出す（ユーザーが確認後に `true` にする）。`publication_name: "10q89s"` を必ず含める。`topics` は Zenn 仕様（小文字・ハイフンなし推奨、5個まで）に従う。

## 出力フォーマット

最終出力は Markdown 1本にまとめる。順序は以下。

1. **タイトル案リスト**（3〜5案、推奨と理由付き）
2. **記事本文ドラフト**（[OUTPUT_TEMPLATE.md](./OUTPUT_TEMPLATE.md) の構成）
3. **「確認が必要」事項リスト**（不明点・推測を避けた箇所）
4. **公開前チェック結果**（[CHECKLIST.md](./CHECKLIST.md) を実行した結果）

ユーザーがタイトルを確定したら、ステップ7の手順で `articles/<slug>.md` を生成して本文を書き込む。ユーザーは確認事項を解消 → `published: true` に変更、というフローで公開する。元の HTML ファイルは記事公開後に削除してよい。

## 文体ルール

- **トーン**: カジュアルすぎず、堅すぎない。社外向け技術広報として自然な「である調」または「ですます調」のどちらかに統一する（ですます調を推奨）。
- **一人称**: 「私たち」「URBAN HACKS のバックエンドチーム」を基本とし、個人名は[DISCLOSURE_GUIDE.md](./DISCLOSURE_GUIDE.md) に従って明示OKの場合のみ使う。
- **技術用語**: 初出は短く補足を入れる。社内用語・社内固有名詞は使わず、一般語に翻訳する。
- **NG表現**:
  - 「最強」「神」「爆速」など過剰な煽り
  - 「弊社では当然〜」のような押し付け
  - 他社・他技術の貶め
  - 「とりあえず」「なんとなく」など曖昧で広報価値のない言い回し
- **誤解を招く表現を避ける**: 「絶対安全」「常に最速」のような断定は避け、文脈・前提を添える。

## AI共同執筆の注記

`## はじめに` 見出しの直前に必ず以下を追加する。

```markdown
:::message
本記事では、生成 AI を利用して共同で執筆しました。
:::

## はじめに
```

## 重要な制約（厳守）

- 社外秘・社内システム名・未公開情報・個人情報・顧客情報は出さない（[DISCLOSURE_GUIDE.md](./DISCLOSURE_GUIDE.md)）
- 不明点は推測で補わない。「確認が必要」事項として明記する
- 発表内容を単に箇条書きで並べず、テーマ・流れで再構成する
- 初回記事ではシリーズ化を意識した導入を必ず入れる
- `published: true` で出力しない（必ず `false`）

## ディレクトリ構成

```
.claude/skills/tech-share-report/
├── SKILL.md             # このファイル
├── INPUT_TEMPLATE.md    # HTMLに書くべき内容のガイド
├── OUTPUT_TEMPLATE.md   # Zenn記事ドラフトの出力テンプレート
├── CHECKLIST.md         # 公開前チェックリスト
├── DISCLOSURE_GUIDE.md  # 社外公開可否の判断観点
└── TITLE_RULES.md       # タイトル案を複数出すルール

articles/tech-share-reports/   # インプットHTML（記事化後に削除）
└── YYYYMM/
    ├── <発表タイトル1>/
    │   └── index.html
    ├── <発表タイトル2>/
    │   └── index.html
    └── ...
```
